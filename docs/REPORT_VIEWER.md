# CareAI Report Viewer — Architecture Documentation

## 1. Patient Information Schema

Patient metadata is extracted from the uploaded document using regular expressions and returned as part of the structured result.

```json
{
  "patient": {
    "name": "Rahul Sharma",
    "age": 28,
    "sex": "Male",
    "sample_date": "05 Sep 2026"
  }
}
```

All fields are optional. If a field cannot be extracted reliably from the document, it is returned as `null`. The UI will display "Not available" for `null` fields. **Patient data is never stored in localStorage, URL parameters, or browser logs.**

### Extraction

- `CBCProcessor.process()` in `backend/app/services/processors/cbc.py` extracts patient info using `re.compile(rf"{keyword}\s*[:\-]?\s*([a-zA-Z0-9\s]+?)(?=\n|$)")`.
- Fields are extracted from the raw text (with newlines preserved for reliable anchor matching).
- If extraction is ambiguous or absent, the field is `None`.

---

## 2. Report Summary

The `summary` object is generated by the mock AI service and contains an uncertainty-aware overview in all three supported languages, along with parameter counts.

```json
{
  "summary": {
    "overview": {
      "en": "Some results are outside the reference range...",
      "hi": "Kuch results reference range ke bahar hain...",
      "hinglish": "Kuch results reference range ke outside hain..."
    },
    "within_range": 2,
    "above_range": 0,
    "below_range": 1,
    "unknown": 0
  }
}
```

CareAI never says "You are healthy" or "You have anemia." All language is uncertainty-aware and neutral.

---

## 3. Parameter Display

Each extracted parameter contains:

```json
{
  "name": "Hemoglobin",
  "value": 10.5,
  "unit": "g/dL",
  "reference_range": "12.0 - 15.5",
  "status": "below_range",
  "explanation": {
    "en": "Your hemoglobin is below the reference range...",
    "hi": "Aapka hemoglobin reference range se kam hai...",
    "hinglish": "Aapka hemoglobin reference range se low hai..."
  }
}
```

**Statuses:**
- `within_range` — Shown in collapsible "Normal Results" section
- `below_range` / `above_range` — Shown in "Values to Pay Attention To" section
- `unknown` — Shown without color coding

The UI uses both color and an icon label to communicate status (never color alone).

## 4. Language Architecture

### Locales

Static UI strings are stored in `frontend/locales/{en,hi,hinglish}.json`. Medical explanations come from the backend's JSON payload.

### i18n Context

`frontend/lib/i18n-context.tsx` provides:
- `language` state — `'en' | 'hi' | 'hinglish'`
- `setLanguage(lang)` — updates state and persists to `localStorage` (key: `careai_lang`)
- `t(key)` — resolves a dotted key path from the current locale

Language preference (`careai_lang`) is the only patient-adjacent value stored in localStorage. Medical report content is never stored in localStorage.

### Language Switching

Switching language is instant — the frontend reads `param.explanation[language]` from the already-loaded JSON. No additional API call is made. Medical values (numbers, units, reference ranges) remain unchanged across all languages.

## 5. English / Hindi / Hinglish Behavior

| Content | English | Hindi | Hinglish |
|---|---|---|---|
| Section headings | "Values to pay attention to" | "Dhyan dene yogya values" | "Dhyan dene yogya values" |
| Medical explanations | "Your hemoglobin is below the reference range..." | "Aapka hemoglobin reference range se kam hai..." | "Aapka hemoglobin reference range se low hai..." |
| Numbers | `10.5` | `10.5` | `10.5` |
| Units | `g/dL` | `g/dL` | `g/dL` |
| Reference ranges | `12.0 - 15.5` | `12.0 - 15.5` | `12.0 - 15.5` |

Hinglish is **natural Hindi in Roman script**, not a word-for-word translation. It uses common Hindi words mixed naturally with English medical terms.

## 6. Privacy Handling

- **Patient data in URLs**: Never. All results are fetched by UUID `report_id` only.
- **Patient data in localStorage**: Never. Only language preference (`careai_lang`) is stored.
- **Patient data in console logs**: Never. The API client removes prior debug logging of patient data.
- **Guest report isolation**: Each guest report is associated with its own UUID. A guest cannot access another guest's report unless they have the exact same UUID.

---

## 7. Medical Safety Boundaries

CareAI is an **informational** system. The `MedicalSafetyValidator` (backend) enforces:

1. **Pydantic schema validation** — the AI output must conform to `AIAnalysisResponse`. Any missing field causes the result to be rejected.
2. **Keyword pattern scanning** — the medical content (excluding limitations) is scanned for unsafe phrases using word-boundary regex: `\bdiagnose\b`, `\bprescribe\b`, `\bstop taking\b`, etc.

The UI never says:
- "You are healthy."
- "You have anemia."
- "Take this medication."

All language is:
- **Simple**: Understandable to a general patient.
- **Neutral**: Neither alarming nor falsely reassuring.
- **Uncertainty-aware**: Uses "outside the reference range shown on this report" not "your value is wrong."

## 9. Report States

| Status | UI Behavior |
|---|---|
| `uploaded` / `queued` / `processing` | Animated progress steps shown |
| `completed` | Full report viewer rendered |
| `failed` | Friendly error with processing_error if available |
| Report not found / fetch error | "Analysis Unavailable" screen |

The UI never shows a default/mock report. If `result` is absent, the parameter sections render empty states.

## 10. Extensibility

To add a new report type (LFT, KFT, Thyroid, etc.):
1. Create `backend/app/services/processors/lft.py` implementing `ReportProcessor`
2. Update `ReportTypeDetector` in `type_detector.py`
3. Update `tasks.py` to route to the new processor
4. Add the new parameter's thresholds to `MockMedicalAnalysisService.analyze()`
5. Add explanations for the new parameters in `en`, `hi`, `hinglish`

To add a new language (Bengali, Tamil, etc.):
1. Add `frontend/locales/bn.json` with translated static strings
2. Update `i18n-context.tsx` to add `'bn'` to the `Language` type
3. Update `LANG_LABELS` in `page.tsx`
4. Add `bn` keys to each `explanation` dictionary in `mock.py`
